## 1. 项目定位

本项目目标是实现一个可以部署演示、可以持续迭代的通用 IoT 平台，而不是只完成几个 CRUD 接口。

当前采用“模块化单体”架构：公共能力拆成独立 Maven Starter，业务暂时集中在唯一可运行服务 `iot-server` 中。等 MQTT 接入、遥测处理等模块出现独立部署需求后，再考虑拆分服务。

项目借鉴 BladeX 的模块划分、自动配置、多租户、日志和注解授权思路，但不会直接复制完整微服务体系。当前优先完成最小可行平台，再持续增加企业级能力。

### 1.1 开发准则

后续开发统一遵守以下准则：

1. **以 `E:\share\iotwater\iot-be` 为主要对标项目。** 开发新模块或公共能力前，先查看对标项目中对应功能的模块职责、分层方式、命名习惯、数据模型和扩展点；能沿用的设计思路优先沿用。对标不等于原样复制，应结合本项目当前的 Spring Boot 3、模块化单体架构和实际业务范围做必要简化。
2. **开发阶段默认跳过自动化测试。** 日常编译、安装和阶段性构建统一使用 `-Dmaven.test.skip=true`，当前阶段以代码编译成功、应用实际启动和关键接口人工验证作为主要验收方式。已有测试失败暂不作为业务开发的阻塞条件；自动化测试体系在核心业务链路完成后集中补齐，除非某个高风险功能明确要求提前增加测试。
3. **基础设施只实现最小可行能力。** 日志、权限、多租户、Redis、监控、部署等基础设施以支撑当前业务闭环为完成标准，不提前追求完整企业级方案。已有基础设施允许在产品、设备、MQTT、遥测和告警开发过程中按实际需求持续迭代，不因非当前必需的完善项阻塞 IoT 核心业务开发。

当对标项目、通用最佳实践和当前阶段目标发生冲突时，优先保证当前业务闭环和可持续演进，并在本文档中记录主动简化项及后续补充时机。

产品与物模型稳定后，再进入设备档案、设备凭证和 MQTT 接入。
